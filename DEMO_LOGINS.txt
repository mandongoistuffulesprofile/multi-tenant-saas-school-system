# SkulApp / Shule Yetu — Local Development Accounts
#
# No passwords are stored in this repository. Every account is created or
# rotated by a command that generates a random password and prints it once;
# store the output in your password manager. Never commit credentials.

## Services
# Backend API: http://localhost:8080
# Frontend SPA: http://localhost:5173
# PostgreSQL:  localhost:5432 (dev-only: school_system / school_admin / dev_secret_password)
# Redis:       localhost:6379

## Fastest local setup

```bash
./launch_all.sh
```

Starts PostgreSQL/Redis (or reuses the local ones), applies migrations and the
demo seed, creates the accounts below if missing, and prints their generated
passwords once. Re-run with `RESET_DEMO_PASSWORD=1 ./launch_all.sh` to rotate the
passwords and print them again.

- School admin: `admin@demo.test`, school code `demo-school`
- SaaS admin:   `platform@demo.test`, school code `platform-ops`

## 1. DEMO SCHOOL TENANT
# The seed creates the tenant, learner and guardian only — no users.
#   cd backend && go run ./cmd/migrate -dir ../migrations -seed
#
# Create the school admin (prints a generated password once):
#   cd backend && DATABASE_URL=postgres://school_admin:dev_secret_password@localhost:5432/school_system?sslmode=disable \
#     DEV_EMAIL=admin@demo.test DEV_PHONE=254700000001 \
#     DEV_ROLE=SCHOOL_ADMIN DEV_TENANT=demo-school \

## 3. TAKE CHARGE WITH YOUR OWN SaaS ADMIN
# Create or update your own platform account and use that to sign in, instead
# of relying on the demo SaaS admin account.
#   cd backend && DATABASE_URL=postgres://school_admin:dev_secret_password@localhost:5432/school_system?sslmode=disable \
#     DEV_EMAIL=you@yourdomain.test DEV_PHONE=254700000000 \
#     DEV_ROLE=SAAS_ADMIN DEV_TENANT=platform-ops \
#     DEV_PASSWORD="YourStrongLocalPassword1!" \
#     go run ./cmd/devuser
#
# Then sign in at /auth/login with that email and password. The demo SaaS admin
# account still exists unless you delete or rotate it yourself.

## 4. ROTATE OR RESET ANY EXISTING ACCOUNT
# Generates a new password and prints it once (or pass NEW_PASSWORD to choose):
#   cd backend && DATABASE_URL=... go run ./cmd/setpassword -email user@example.com

## 5. PWA / INSTALL PROMPT
# The app is PWA-ready: it ships a manifest, icons and a service worker. On a
# supported browser, opening the app home screen may trigger the browser's own
# install prompt. The app also shows a polite “Add Shule Yetu” card when the
# browser offers the install event.

## 6. BEFORE PRODUCTION
# - Demo/seed data is only applied with the -seed flag and is refused when
#   APP_ENV=production.
# - Delete demo tenants and accounts, and rotate every dev password.
